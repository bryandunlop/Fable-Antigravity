Offline — What does the developer need to see?

The app already works offline via localStorage. This is about showing the developer what real offline sync should look like. How much detail?

A

Offline Banner Only

A simple banner at the top when connectivity is lost. "You're offline — changes will sync automatically when your connection is restored." Disappears when back online. Simple, low-fidelity, communicates the intent.

📡 You're offline · 3 changes pending sync
B

Sync Queue Panel

Banner + a "Pending Changes" panel accessible from the banner or sidebar. Lists what's queued: "Inspection N5PG submitted (offline)", "Stock update: +12 water". Developer sees the exact data structure they need to build the sync API around.

Pending Sync · 3 changes
📋 Inspection submitted — N5PG · 14 min ago
📦 Stock update — +12 water bottles · 32 min ago
✏️ Par level changed — Coffee pods → 24 · 1h ago
C

Per-Record Sync Status

Each inspection card, stock entry, and request shows a sync status icon: ✅ synced, 🕐 pending, ❌ failed. The developer sees exactly which records need sync endpoints. Most technically informative but most work to build in the demo.

Inspection — N5PG · today 🕐 pending
Inspection — N6PG · yesterday ✅ synced
Stock update — water · 2d ago ❌ failed
